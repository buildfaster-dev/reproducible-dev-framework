## 1. Introducción

Todo proceso de construcción declarativa comienza con una acción simbólica:  
**vaciar el espacio**.

Resetear tu entorno no es una tarea técnica, sino un acto de intención.  
Borras lo innecesario para hacer visible lo esencial: lo que eliges mantener.  

Este documento te guía en la **fase cero** del Reproducible Dev Framework:  
una limpieza consciente que prepara tu sistema operativo, tu mente y tu flujo de trabajo  
para la creación de un entorno reproducible.

---

## 2. Por qué resetear

Cada entorno de desarrollo refleja años de hábitos acumulados:  
comandos globales, configuraciones fragmentadas, herramientas instaladas sin contexto.  

El problema no es técnico, sino filosófico:  
perder el control sobre tu sistema es perder autonomía.

> Resetear es declarar el inicio de una nueva práctica:  
> todo lo que se instale a partir de ahora será **intencional, reproducible y portátil.**

El reset no busca velocidad, sino **claridad**.  
Cuando eliminas lo obsoleto, creas espacio para lo esencial.

---

## 3. Principios de limpieza consciente

Este paso se basa en tres principios fundamentales del framework:

| Principio | Descripción |
|------------|-------------|
| **Nada global** | Ninguna herramienta debe existir fuera de tu control o sin declararse explícitamente. |
| **Todo declarativo** | Las instalaciones deben poder reproducirse desde un archivo o flake. |
| **Control total** | Tu entorno es tuyo: entiendes cada archivo, cada proceso y cada dependencia. |

Al aplicar estos principios, el reset deja de ser una operación destructiva  
y se convierte en un ritual de **recuperación de soberanía técnica**.
